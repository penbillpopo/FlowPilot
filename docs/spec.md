# FlowPilot 需求與架構

版本 0.3（2026-10-07）｜取代 `ai_workflow_orchestrator_development_spec.docx` 的架構部分，需求以本文件為準。

變更紀錄
- 0.3：不用工作樹，改用四個固定資料夾；AI 做完由你審查後按「提交」；不推送；不處理 Sentry；Jira 帳密沿用 JiraMcpServer 專案的設定。
- 0.2：初版（工作樹方案）。

---

## 1. 目標

**一個在背景常駐的「每日任務代理」**。你說「執行開發任務」，它把 Jira 上進行中的單整理成計畫給你確認；確認後批次建立分支，在固定的專案資料夾裡替每張單開一個 Codex 執行你寫好的開發技能，並把所有 AI 的進度與提問集中給你。

### 做
- 每日開發流水線（本文件的主體）
- 集中處理多個 AI 的提問與回答
- 在 VS Code 裡即時看到每個資料夾的 AI 在做什麼
- 中斷後可以恢復
- 預留本機介面給 typeless 用語音操作

### 不做（第一版）
- 不由 FlowPilot 自己寫程式；寫程式一律交給 Codex 加上你的技能
- 不用「點畫面、貼文字」的方式控制 AI
- 不推送分支（`platform-web-copy` 自己的推送除外，見 4.3）
- 不刪除分支，不暫存或丟掉你的改動
- 不做通用的流程編輯器；第二條流程出現時再抽象化

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| 單 | Jira 上的一張 issue，例如 `ALL-14699` |
| 工作項目 | 一張單在一個專案（和商戶）上要做的事，對應一條分支、一段 AI 對話 |
| 資料夾 | 四個固定的專案資料夾之一，一次只能做一個工作項目 |
| 來源商戶 | 多商戶的單，先開發的那個商戶 |
| 目標商戶 | 多商戶的單，之後用 `platform-web-copy` 移植過去的商戶 |
| 計畫表 | 你確認前看到的表格：單、專案、商戶、分支、技能、標題 |

## 3. 流水線

```
① 列出單      Jira：指派給我、狀態為進行中
② 你勾選      這次要做哪幾張                                        ← 確認點一
③ AI 判斷     讀每張單的上下文 → 專案、商戶、來源商戶、合併請求標題
④ 算分支      依規則算出分支名稱 → 先抓遠端 → 檢查是否已存在
⑤ 計畫表      專案、商戶、分支、技能、標題，每格可改                ← 確認點二
⑥ 建立分支    全部一次建好，但不切換
⑦ 分配執行    資料夾空出來就切到該分支，開一段 Codex 對話執行技能
⑧ 追蹤        集中顯示進度與提問；你在 FlowPilot 或 VS Code 回答
⑨ 審查提交    AI 做完 → 你審查 → 按「提交」→ 資料夾空出來接下一張  ← 確認點三
⑩ 移植        （只有多商戶的單）提交後 → 你說可以 → 執行 platform-web-copy  ← 確認點四
```

### 3.1 各步驟細節

**① 列出單**
- 查詢條件：`assignee = currentUser() AND status = "In Progress"`（要用狀態的原始名稱，畫面上的「進行中」是翻譯名稱，查不到；UAT、READY TO TEST 雖然也屬於「進行中」類別，但不會被抓進來）。
- 指派給你的大多是 `[FE]` 子任務，會一併顯示上層主單。
- 顯示：單號、標題、狀態、更新時間、子單（`[FE]`、`[BE]`）。

**② 你勾選**
- 系統不會替你選，一定由你勾選。

**③ AI 判斷**
- 由 Codex 用一段**不留紀錄的臨時對話**判斷，並用固定的資料格式輸出（`outputSchema`），不接受只有文字的答案。
- 輸入：主單與子單的標題、內文、留言，以及你過去的修正紀錄（見 7.3）。
- 輸出：每張單的「專案清單」；PlatformWeb 的單另外輸出「商戶清單」；每個判斷都附上理由。
- 商戶判斷不出來時留空，讓你填。

**④ 算分支與檢查**：見第 4 節。

**⑤ 計畫表**
- 每格都可以改：專案、商戶、來源商戶、技能、合併請求標題。
- 已建立的工作項目標示「此分支已建立」，整張單不會執行。
- 一張一張確認：每張單按自己的「確認 KEY，開始開發」就進入 ⑥，沒有一次全部確認的按鈕。

**⑥ 建立分支**
- 分配到資料夾時，在那個資料夾從遠端最新的基底分支建立分支再切換：
  `git branch --no-track ban/m8/ALL-14699 origin/master-8` → `git switch ban/m8/ALL-14699`
- 開分支前先 `git fetch`，所以起點一定是遠端最新版。
- 實作時改成「分配到資料夾時才建立」，不在確認當下一次建好：PlatformWeb 有兩個獨立複本，事先不知道會分到哪一個，建在錯的複本另一個看不到。

**⑦～⑩**：見第 5、6 節。

## 4. 規則

### 4.1 分支規則

| 專案 | 商戶 | 基底分支 | 新分支 |
|---|---|---|---|
| PlatformWeb | 1、2、5、7、8、9、10 | `master-{商戶}` | `ban/m{商戶}/ALL-xxxxx` |
| PlatformAdmin | — | `version/0.0.1` | `ban/ALL-xxxxx` |
| GoMoneyAdmin | — | `version/0.0.1` | `ban/ALL-xxxxx` |

- 單號一律大寫。
- **分支用子任務的單號**（指派給你的那張），在計畫表裡確認；被指派的本身是主單時，就用主單的單號。
- 規則放在設定檔，之後新增商戶或專案不用改程式。

### 4.2 「已建立」的判斷
- 檢查前一定先 `git fetch`。
- **名稱完全相同**才算已建立；其他名稱（`-2`、`ban/master/…`、別人的分支）一律不管。
- 要檢查的地方：該專案**所有資料夾的本機分支**，加上遠端。（PlatformWeb 和 PlatformWeb-2 是獨立複本，在其中一個建立的分支另一個看不到。）
- 一張單只要有任何一個工作項目已建立，**整張單停止**，並提醒你「此分支已建立」。

### 4.3 多專案、多商戶
- 一張單牽涉多個專案：拆成多個工作項目，在計畫表裡確認。
- PlatformWeb 多商戶：
  - 來源商戶優先順序：**m1 > m5 > m8 > 其他**（數字小的優先）。
  - 只建立來源分支，並在上面跑開發技能。
  - 目標分支**不預先建立**，由 `platform-web-copy` 自己建立。
  - 來源經你審查、提交後，系統詢問你「可以移植嗎？」，你同意後在**同一個資料夾**執行 `platform-web-copy`。
  - 來源分支不推送，所以送給技能的內容會註明「來源分支只在本機，不要對它執行 pull」。
  - `platform-web-copy` 會自己推送目標分支並開合併請求，這是技能本來的設計，FlowPilot 不干涉。

### 4.4 合併請求標題
- 格式：`feat(ALL-xxxxx) 英文描述`，單號與分支相同（子任務的單號），由 AI 依照 Jira 標題擬稿，在計畫表裡確認。
- 同時也是 ⑨ 提交時的提交訊息。

## 5. 資料夾與執行

### 5.1 四個固定資料夾

| 資料夾 | 路徑 | 專案 |
|---|---|---|
| PlatformWeb | `~/Desktop/Project/PlatformWeb` | PlatformWeb |
| PlatformWeb-2 | `~/Desktop/PlatformWeb-2` | PlatformWeb |
| PlatformAdmin | `~/Desktop/Project/PlatformAdmin` | PlatformAdmin |
| GoMoneyAdmin | `~/Desktop/Project/GoMoneyAdmin` | GoMoneyAdmin |

- 同時最多 4 個工作項目，而且是**每個專案各自的名額**：PlatformWeb 2 個，其他各 1 個。其餘排隊。
- 資料夾清單放在設定檔，之後要加資料夾不用改程式。

### 5.2 分配規則
- 資料夾要同時符合這幾個條件才能接新工作：沒有工作項目在跑、沒有等你審查的改動、`git status` 是乾淨的。
- 不乾淨時停下來問你，**不會自己暫存或丟掉改動**。
- PlatformWeb 有兩個套件群組：**群組 A：1、2、7、8**；**群組 B：5、9**（10 之後再補）。分配時優先挑「目前分支同群組」的資料夾；跨群組時，切換後先執行 `npm install` 再開始。
- 切換後如果 `package-lock.json` 跟切換前不同，也會先執行 `npm install`。

### 5.3 資料夾的佔用狀態

```
空閒 → 切換分支 →（安裝套件）→ AI 執行中 ⇄ 等你回答 → 等你審查 → 提交 → 空閒
                                                  多商戶：提交 → 等你同意移植 → 移植中 → 空閒
```

你的 `frontend-workflow` 規定「沒有要求就不提交」，所以 **AI 做完後，資料夾會一直佔用到你審查並提交為止**。

### 5.4 你自己也會用這些資料夾
- FlowPilot 正在使用的資料夾，會在 FlowPilot 畫面和 VS Code 終端機分頁標題上標示「FlowPilot 使用中」。
- 使用中請不要手動切換分支。如果偵測到分支被切走，FlowPilot 會暫停那個工作項目並通知你。

## 6. AI 執行

### 6.1 用 Codex 共用常駐服務
- FlowPilot 啟動 Codex 的**本機共用常駐服務**（`codex app-server daemon`），用 WebSocket 連上它。
- 使用你的 ChatGPT 訂閱，不使用 API 金鑰（啟動時移除 `OPENAI_API_KEY` 等環境變數）。
- 每個工作項目建立一段對話，對話名稱設為「單號｜商戶｜資料夾」，在各處都能辨認。
- 送出的內容：技能（`UserInput` 的技能類型）＋ **主單**的 Jira 網址 `https://inta.atlassian.net/browse/ALL-xxxxx`（需求內容寫在主單上）。

### 6.2 技能
- 技能清單從 Codex 讀取（`skills/list`），在計畫表裡選，預設是 `frontend-workflow`。
- 移植階段固定使用 `platform-web-copy`，輸入資料由系統依照計畫表自動產生。

### 6.3 狀態
- 「等你回答」的判定：Codex 發出提問請求（`requestUserInput`、執行同意請求），或一輪工作結束時最後一段回覆是在問問題。
- 你的技能有很多會停下來問的地方（例如瀏覽器測試前一定會先給你確認測試計畫），所以這是常態，不是例外。

### 6.4 回答提問
- 可以在 FlowPilot 的畫面回答，也可以直接在 VS Code 那個資料夾的終端機分頁回答；兩邊連的是同一段對話，結果一致。
- 系統通知：「ALL-14699 在等你回答：……」，點一下就跳到該題。

### 6.5 審查與提交（做法甲）
- AI 做完後，FlowPilot 顯示：改了哪些檔案、差異摘要、AI 的最後報告，並可以一鍵在 VS Code 打開差異。
- 你按「提交」：由 FlowPilot 直接執行 git 提交（不是交給 AI），提交訊息使用計畫表裡的合併請求標題，**不推送**。
- `src/environments/environment.ts` **預設不勾選**：瀏覽器測試技能會為了切換 SIT／UAT 修改這個檔案，而且不會改回來。提交後，FlowPilot 會把這個檔案還原，資料夾才會是乾淨的。如果這張單真的需要改它，你可以手動勾選。
- 你也可以按「退回」，補一句話交給同一段對話繼續修改。

### 6.6 執行權限與環境
- 沙箱：資料夾內可寫入，需要網路（npm、Jira、Playwright）。
- 指令同意：一般指令自動同意；`git push`、刪除分支、`reset --hard` 等交給你確認（移植階段的推送除外）。

## 7. VS Code 與其他

### 7.1 VS Code 呈現（已實測可行）
- 固定一個工作區檔 `FlowPilot.code-workspace`，包含四個資料夾，用 `code` 指令打開。
- 每個資料夾一個終端機分頁，執行 `codex resume <對話編號> --remote unix://`，接上該資料夾目前那張單的 AI，即時看到思考、指令、輸出、回覆，也可以直接打字。
- 資料夾換到下一張單時，分頁會重新接上新的對話。
- 開分頁的方式：FlowPilot 輔助外掛（`resources/vscode-companion/`，第一次自動安裝）收到網址 `vscode://flowpilot.flowpilot-companion/attach?...` 就開分頁。第一次 VS Code 會詢問是否允許，勾「不要再詢問」即可。
- 對話要等第一輪開始後才接得上（實測：還沒開始時接續會失敗），所以開分頁在送出技能之後。
- 同意請求會同時送到 FlowPilot 與 VS Code 分頁（已實測），任一邊回覆都有效。
- 為什麼不用 Codex 側邊面板：VS Code 的 Codex 外掛會自己另外啟動一個 Codex 服務，實測時，另一個服務去接正在執行的對話會被拒絕（`thread already has an active writer`），所以側邊面板只能在完成後查看紀錄。

### 7.2 修正紀錄
- 你在計畫表裡改過的專案、商戶判斷都會記下來（單的摘要 → 你的決定），下次判斷時一起交給 AI 參考。

## 8. 應用程式架構

### 8.1 技術
| 項目 | 選擇 |
|---|---|
| 應用程式 | Electron + TypeScript（選單列圖示＋主視窗，關掉視窗也會在背景繼續跑） |
| 資料 | SQLite，存在 `~/Library/Application Support/FlowPilot/` |
| Codex 串接 | 官方產生的 TypeScript 通訊型別（`codex app-server generate-ts`） |
| Jira | REST API；網址、帳號、權杖沿用 `~/Desktop/Project/JiraMcpServer` 的 `.env` 與 `token.txt`（路徑放在設定檔，執行時讀取） |
| 設定 | `~/Library/Application Support/FlowPilot/設定.yaml`（分支規則、資料夾、套件群組） |

### 8.2 為什麼做成應用程式
- macOS 會保護「桌面」資料夾，你的專案都在桌面底下。有簽章的應用程式能正常跳出授權詢問，背景程式容易被系統默默擋掉。
- 有系統通知、選單列圖示、開機自動啟動。
- 不用開著瀏覽器分頁，關掉視窗後仍在背景執行。

### 8.3 模組

```
src/
  main/                 應用程式主程序
    jira/               Jira 查詢
    planner/            AI 判斷、分支計算、已建立檢查、計畫表
    git/                fetch、建立分支、切換、提交、狀態檢查
    folders/            四個資料夾的佔用狀態、分配、套件群組
    codex/              常駐服務連線、對話、技能、提問偵測
    runner/             排程、狀態機、恢復
    vscode/             工作區檔、終端機分頁
    store/              SQLite
    api/                本機介面（給 typeless）
    notify/             系統通知、選單列
  renderer/             畫面：單列表、計畫表、資料夾看板、提問、審查
```

### 8.4 恢復
- 每次狀態改變都先寫進資料庫再執行下一步。
- 重新啟動後：重新連上 Codex 常駐服務，用對話編號接回每段對話，檢查每個資料夾目前的分支是否跟紀錄相符，不會重複建立分支。
- 建立分支、切換、提交前都先檢查現況（重複執行也安全）。

## 9. typeless 整合（介面先預留，第一版不改 typeless）

FlowPilot 在本機開一個介面（Unix socket，`~/Library/Application Support/FlowPilot/api.sock`）。

| 方向 | 動作 |
|---|---|
| typeless → FlowPilot | 啟動開發任務、查詢進度、列出等你回答的問題、回答某張單的問題、確認計畫、提交、停止某張單 |
| FlowPilot → typeless | 計畫擬好了、某張單在等你回答、某張單等你審查、完成或失敗 |

- typeless 那邊之後只需要：在動作池加一個呼叫 FlowPilot 的基本能力，並訂閱 FlowPilot 的通知、顯示在指令島上。
- 計畫表用聽的不好確認，所以計畫顯示在 FlowPilot 的視窗，確認和修改可以用說的。

## 10. 安全
- 不推送（移植技能自己的推送除外）、不刪除分支、不暫存或丟掉你的改動。
- 唯一會自動還原的檔案是 `environment.ts`，而且只在你按「提交」之後、只還原 AI 改的那一份。
- Jira 權杖只在執行時從 `token.txt` 讀取，不複製、不寫進 FlowPilot 的設定檔、紀錄檔或 AI 的指令。
- Jira 的內容一律視為資料，不會被當成給系統的指令。
- 每個工作項目保留完整紀錄：送給 AI 的內容、AI 執行的指令、改了哪些檔案、你的每次確認。

## 11. 實測結果（2026-10-07）

| 項目 | 結果 |
|---|---|
| 從程式啟動 Codex 對話並收到完整進度 | 可行 |
| 兩個獨立的 Codex 服務接同一段進行中的對話 | **不行**（會被拒絕）→ 不用側邊面板觀看 |
| 共用常駐服務：第二個連線中途接上 | 可行，之後的事件全部即時收到 |
| 終端機版 Codex `--remote` 接上進行中的對話 | 可行，畫面即時顯示指令、輸出、回覆，標題顯示對話名稱 |
| 工作樹裡切換到別的資料夾正在用的分支 | 不行（git 的限制）→ 改用四個獨立資料夾，問題消失 |

## 12. 開發階段

| 階段 | 內容 | 驗收方式 |
|---|---|---|
| 1. 骨架與列單 | 應用程式外殼、設定檔、SQLite、Jira 連線、列出進行中的單並勾選 | 打開應用程式，看到你自己的進行中單 |
| 2. 計畫表 | AI 判斷、分支計算、抓遠端並檢查已建立、計畫表編輯與確認、修正紀錄 | 用真實的單產生計畫表，判斷結果和分支名稱正確 |
| 3. 資料夾與分支 | 建立分支、資料夾看板、分配、切換、套件群組 | 確認後分支建好，資料夾正確切換 |
